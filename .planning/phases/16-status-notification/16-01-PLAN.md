  <behavior>
    - Stage mapping: 'triggered' -> stage 0 ("Payment confirmed"), 'provisioning' -> stage 1 ("Setting up your server"), 'installing'/'creating_user'/'sending_email' -> stage 2 ("Installing your garden"), 'complete' -> stage 3 ("Your garden is ready!")
    - Each stage has state: 'completed' (index < current), 'active' (index === current), 'pending' (index > current)
    - 'failed' status sets currentStageIndex to -1
    - 'unknown' status (no data yet) sets currentStageIndex to 0
    - isComplete is true only when status === 'complete'
    - isFailed is true only when status === 'failed'
    - siteUrl and loginUrl are populated from poll response when status is 'complete'
    - error is populated from poll response when status is 'failed'
    - Polling does NOT start if sessionId is undefined/empty
    - Polling stops (pause called) when terminal state reached
    - Countdown: count starts at 240 and decrements; timeRemaining formats as "M:SS" (e.g., "3:45")
    - Countdown pauses when isComplete becomes true
  </behavior>
  <implementation>
    Create `app/composables/useProvisioningStatus.ts` following the research Pattern 1 (useTimeoutPoll) and Pattern 2 (useCountdown). Key implementation details:

    1. Define STAGES array mapping raw statuses to 4 human-facing stages (see research Pattern 1)
    2. Use `useTimeoutPoll` from @vueuse/core with 3000ms interval and `immediate: true`
    3. Poll `$fetch('/api/provision-status', { query: { session_id: sessionId } })` — type the response matching handleProvisionStatus return shape
    4. Derive `stages` computed array with state ('completed'/'active'/'pending') per stage
    5. Use `useCountdown(240)` for the timer, expose formatted `timeRemaining` as "M:SS"
    6. Watch `isComplete` to pause countdown
    7. Guard: if `!sessionId`, don't start polling (call pause immediately)
    8. Guard: call `pause()` inside poll function when terminal state detected

    Export: `useProvisioningStatus(sessionId: string | undefined)` returning `{ status, stages, currentStageIndex, isComplete, isFailed, siteUrl, loginUrl, error, timeRemaining, count, pause }`

    For unit tests: Mock `$fetch` globally (vi.stubGlobal). Since useTimeoutPoll and useCountdown require Vue reactivity context, test the pure logic functions (stage mapping, formatting) as extracted helpers, and test the composable's initial state and guard behavior. Use vi.useFakeTimers() for countdown tests.

    Note: The composable uses `useTimeoutPoll` and `useCountdown` from @vueuse/core (already installed, confirmed in research). Use CSS keyframes + Tailwind for animations (not @vueuse/motion) per planning context — v-motion is only for mount/enter transitions in the UI components (Plan 02).
  </implementation>
